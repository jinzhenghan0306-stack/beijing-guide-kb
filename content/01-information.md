# 01 · 信息获取

> **核心原则：全面靠结构，不靠搜得多。稳定靠冗余，不靠单点。简洁靠过滤，不靠删减。**

## 一、信源矩阵（保全面）

"全面" = 四类信源结构互补，缺一不可：

| 信源层 | 具体渠道 | 作用 |
|---|---|---|
| 官方权威 | beijing.gov.cn、北京日报、市交通委、北京地铁/京港地铁公告 | **准确性的底牌**，民生号错一条就掉粉 |
| 权威媒体 | 新京报、北京晚报、1039交通广播 | 兜底，覆盖官方不发的日常变化 |
| 搜索 + 新闻API | 腾讯新闻 API Key、WebSearch | 自动化采集主力，广撒网 |
| 平台趋势热榜 | 微博北京同城、小红书热榜 | 用户此刻真正关心什么，选题包装的原料 |

## 二、采集引擎（保稳定）

任何单一信源都会挂（限流、封key、改版）。三通道互备：

1. **搜索** → 挂了用 **新闻API** → 都挂了直接**爬官方源** → 还不行降级成"给人工的采集提示"
2. 采集结果**当天落盘归档**——数据不丢，永远可以溯源
3. 采集节奏：**T-1 早 9 点**（覆盖当天变化）

## 三、过滤漏斗（保简洁）

"简洁明了有概括性"靠上游狠过滤：

```
全量 100 条 → 规则去重（时间/地域/类别/黑名单）→ AI 打分 → 交叉验证 → 剩 5-6 条
```

## 四、真实性三级闸门

1. **信源分级**：只采用官方/权威媒体背书的信息；低可信源必须找到官方出处才能用
2. **交叉验证**：地铁停运、交通管制、停电停水这类"错了就完蛋"的，必须两个独立信源一致
3. **T-0 复查**：T-1 采集到发布之间信息可能已变，上午发稿前对每条验一遍最新状态

> [!warning] 翻车红线
> 紧急信息（临时封路、极端天气）永远插队优先。宁可少发，不能发错。

## 五、时效节奏

| 环节 | 时间 | 动作 |
|---|---|---|
| T-1 采集 | 早 9:00 | 自动采集当日变化 |
| T-0 验证 | 上午 | 逐条复查最新状态 |
| 发布 | 晚 19-20 点 | 当天变化尘埃落定，打工人刷手机高峰 |
