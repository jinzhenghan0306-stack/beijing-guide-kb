# 05 · 发布运营

> **时效性账号的生命线：宁可少发，不能晚发。**

## 一、发布节奏

| 规则 | 值 |
|---|---|
| 发布时间 | **晚 19:00-20:00**（打工人通勤完、晚饭后刷手机高峰） |
| 发布频率 | 攒够 5-6 条就发，两三天一篇 |
| 极端天气/紧急信息 | 插队，立即发 |
| 标题固定 | `北京X月X日生活指南` |

## 二、发后 2 小时互动（黄金窗口）

- 发布后 **2 小时内**回复所有评论 —— 提升算法互动权重
- 主动在自己的评论区置顶一条补充信息（如"更新：XX 路段已恢复通行"）
- 回复要有信息增量，不敷衍（"谢谢"无效，要提供新信息）

## 三、评论区运营

- 用户报错/纠错 → 核实后置顶更正，**别删评**
- 重复问题 → 提炼成置顶 FAQ
- 用户补充的本地信息（"我家附近新开了XX"）→ 记入选题库，这是免费的情报

## 四、数据复盘模板（每篇发布 24-48h 后）

```
标题：____________  发布时间：____________
浏览量：____  点赞：____  收藏：____  评论：____  分享：____
收藏率（收藏/浏览）：____  ← 最核心指标，目标 8%+
互动率（赞藏评/浏览）：____  ← 目标 5%+
---
表现最好的信息卡：____（说明该类选题用户买单）
表现最差的：____
下次改进：____________________
```

## 五、KPI 基准

| 指标 | 目标 |
|---|---|
| 收藏率 | 8%+（实用性验证） |
| 互动率 | 5%+ |
| 评论质量 | 30%+ 是有信息量的评论 |
| 分享率 | 2%+ |
| 月涨粉 | 15-25% |

## 六、迭代机制

1. 每周看一次数据复盘
2. 高收藏的选题 → 做成系列（如"北京通勤避坑"系列）
3. 高评论的钩子 → 固定成标准钩子
4. 低表现类别 → 调整或砍掉
5. 所有结论回流更新到对应知识库模块
